# 花椰菜相機（Broccoli-Cam）

給知識型、口播型新手創作者的極簡拍攝工具。iOS 原生（SwiftUI + AVFoundation）。

完整規格在 [`docs/spec-v1.1.html`](docs/spec-v1.1.html)。

## 目前進度：第一輪

已實作：

- 前鏡頭直式錄影（依裝置實際支援提供 1080p／4K、30／60 FPS），HEVC，存到照片圖庫
- 提詞：整篇貼上、固定在螢幕頂端緊鄰前鏡頭、自動捲動＋手動滑動、字級／速度／底色可調、與錄影各自獨立啟停
- 固定頭像框，提詞開始後淡出；頭像框與提詞都不會錄進影片
- 臉部定位（`AVCaptureMetadataOutput`）：位置大致正確時頭像框變色
- 收音檢查與說話偵測（讀錄影音訊連線的 `audioChannels`，不另開 `AVAudioEngine`）
- 錄影倒數、錄影完成頁（預覽／儲存／重錄）
- 設定記憶（UserDefaults）
- App 內除錯資訊層

## 第二輪（尚未真機驗證）

- 分段錄影：稿件用空行分段，一段錄一次；錄完選「留用」或「重錄這段」，全部錄完自動接成一支。沒有空行就是一整段，流程和第一輪相同
- 完成頁可以回去只重錄其中一段，再重新接片
- 接片時裁掉每段頭尾沒有聲音的部分（可在設定關閉）
- 錄影中停頓時提詞自動暫停，開口再繼續（可在設定關閉）
- 稿件頁顯示字數、預估時長、段數；錄影計時旁顯示這一段的預估時長
- 音量鍵、藍牙自拍遙控器可以開始／停止錄影，剛錄完一段時等同「留用」（iOS 17.2 以上）

## 第三輪（尚未真機驗證）

- 語音跟隨提詞：設定裡打開「提詞跟著我的聲音走」，錄影時唸到哪，提詞就捲到哪。預設關閉。講了約 6 秒還對不上稿子，會自動改回固定速度
- 字幕檔：完成頁按「產生字幕檔（SRT）」，用稿子對影片的聲音，字用稿子裡的，辨識只負責找時間。做好後跳出分享選單，可以存到檔案或傳到剪輯 App
- 字幕每行最多字數可以在設定調（預設 14 字）
- 手機不能辨識中文時，有稿子仍會給字幕檔，時間照字數平均排；沒有稿子就直接用聽到的字
- 稿件頁列出每一段的預估時長，分段列也顯示這一段要講多久

語音辨識用 Apple 的 Speech 框架，語言固定 zh-TW。手機支援裝置端辨識就不連網；不支援時聲音會送到 Apple 辨識。

## 第四輪（尚未真機驗證）

- 陪伴模式（第十輪拆成「看多少字」和「有人聽」，見下面）：主畫面收音圖示旁的「提詞／陪伴」可以切換，設定頁最上面也有。陪伴模式不看稿，鏡頭旁邊有一位聆聽者，講話時偶爾點頭。聆聽者不會錄進影片
- 橫式錄影：手機橫著架，錄出來就是 16:9。介面仍鎖直式，橫放時提詞、頭像框、按鈕圖示、計時各自轉 90 度（和系統相機同一種做法）。可在設定關閉
- 橫放時提詞變成鏡頭旁邊的一直欄
- 分段錄影時每一段的擺法要一樣，不一樣會跳提示，不讓錄

規劃見 [`docs/需求缺口與功能規劃.md`](docs/需求缺口與功能規劃.md)。

## 第五輪（尚未真機驗證）

- 聆聽者換成 AI 產的預錄短片：一位風格化 3D 的女性，9:16，待機 3 支、點頭 2 支，沒有微笑（微笑會干擾，只要顯得專心）。待機片隨機輪播，你講話時偶爾淡入點頭片，播完淡回待機。片子沒有音軌，播放器也靜音
- 每支片的第一格和最後一格都是同一張定格圖，切換時看不出接縫。素材怎麼做的、提示詞、驗收方式寫在 [`docs/聆聽者短片分鏡.md`](docs/聆聽者短片分鏡.md)，轉檔用 `tools/companion_clips.py`
- 聆聽者擺法可以切換（第六輪改過，見下面）
- 片子放在 `BroccoliCam/Resources/Companion/`，播放邏輯在 `CompanionClipPlayer`，點頭時機仍在 `CompanionModel`

## 第六輪（QC-0005，尚未真機驗證）

- 前鏡頭預覽整個主畫面只有一個，換擺法只改大小和位置。以前每換一次就重建預覽層，畫面會卡住，自己的畫面也會一直黑
- 主畫面的「提詞／陪伴」按下去跳選單，提詞和六種陪伴擺法一次選好（第十輪改過，見下面）。設定頁用同一組按鈕
- 拿掉上下分割，加三種擺法：眼神條、完整取景、對位再開講。每一種裡自己的畫面都是完整 9:16，頭在預覽的哪裡，錄出來就在哪裡。小窗裡也有頭像框。橫放時除了圓形頭像，其他都改用頂部小窗
- 頭像框跟著人的遠近縮放，脖子和肩膀的比例由頭的大小推算。倍率在 `FaceDetectionService.head(from:)`
- 語音跟隨時，唸過的字變綠。語音跟隨改成預設打開，第一次有稿子時會問語音辨識權限
- 設定頁的說明文字全部拿掉，選項放大

## 第七輪（尚未真機驗證）

- 腳本列表：按「稿件」先進列表，可以新增、改名、複製、長按拖曳排序、左滑刪除、匯入 txt 和 md、分享。原本那篇稿自動變成第一篇。存在 Application Support 的 `scripts.json`
- 草稿字改大，跟著系統字級走，編輯頁有「A−／A＋」
- 一鍵優化：主畫面的魔術棒。讀目前的畫面，算出曝光、色溫、色調、亮部、暗部、對比、自然飽和度、降噪、銳利，每一項都能自己拉，可以按住比對、整組還原。柔膚要自己拉。曝光到極限臉還是太暗，會提示靠近光源。判斷全在手機上算，不連網
- 錄影核心換掉：原本用 `AVCaptureMovieFileOutput`，現在每一格畫面自己處理再用 `AVAssetWriter` 寫檔（`FrameRecorder`）。優化開著時，預覽和錄出來的是同一個樣子
- 防抖：關、標準、加強，這支手機不支援的不顯示。預設關
- 主畫面側邊一條快速開關：語音跟隨、一鍵優化、構圖線、防抖
- 構圖線三選一：關、頭像框、九宮格，濃淡可調。頭像框提詞開始後淡出，九宮格降一半
- 跳轉：提詞旁有上下兩顆鍵，點任何一行也會跳過去。語音跟隨可以退回去重唸
- 藍牙控制：設定裡可以測試按鍵、替每個動作指定按鍵。預設 ↓ → PageDown 往下，↑ ← PageUp 往上，空白鍵／Enter／句號暫停或繼續，C 開關語音跟隨，M 切換逐段和逐行。只會送音量鍵的自拍遙控器不能拿來跳轉，音量鍵給錄影用了
- 分段錄影可以在設定關掉，整篇一鏡到底
- 已經錄了幾段才換稿，會先問要不要刪掉
- 分段錄到一半切到陪伴，已錄的段落先收著，切回提詞原樣接著錄；陪伴期間改過稿，切回來才問（第十輪起是切到「不看」才收著）
- 寫檔失敗、或只救回一部分，會跳視窗講清楚

規劃見 [`docs/第七輪計畫.md`](docs/第七輪計畫.md)。

## 第八輪（尚未真機驗證）

- 錄影檔改放 Application Support 的 `takes`，每次狀態改變就記到清單（`TakeStore`）。app 被滑掉，重開會問要接著錄還是刪掉；錄到一半被滑掉的那段也救得回來（至少半秒）。還沒儲存的完成影片一樣會問
- 清單寫成功才刪檔；讀不到清單就什麼都不刪；清單壞掉會改名留底，能播的逐支救成影片
- 提詞的畫面和點擊換算共用同一份 TextKit 排版（`PromptLayout`），有空行的長稿點哪行就跳哪行
- iOS 17 開優化時改用 CoreMedia 的 709 色彩空間，暗部不再偏亮
- 聆聽者三位可選：選單和設定頁都有頭像
- 聆聽者即時反應（設定可關，預設開）：講完一句停頓時點頭、突然大聲時抬眉、停很久時歪頭等、重新開口時往前靠。只看音量，在手機上算。判斷在 `ListenerReactor`
- 字幕燒進影片這一輪只寫了方案，第九輪才做：[`docs/字幕燒入方案.md`](docs/字幕燒入方案.md)

## 第九輪（尚未真機驗證）

字幕燒進影片，做完方案的第 0 到 2 期。

- 流程：完成頁按「加字幕」，對好字幕後進校對頁，黃色的句子全部確認過才能按「燒錄」。燒好會自動存進照片，原片留在 app，另外有「存原片」「分享」「看 SRT」。需要連網辨識時，「加字幕」下面寫「聲音會送到 Apple 辨識」
- 有稿子就用稿子的字，辨識只管時間。對上七成以上直接用（第十輪起，數字不一樣或一字之差的也標黃）；三成到七成標黃，給「用稿子的」「用聽到的」兩個選；三成以下標「沒講到」，預設不燒；聽到但稿子沒有、連續四個字以上的插一句標黃。某一段辨識失敗，碰到那段的句子標「沒辨識到」，不算漏講；整支都沒辨識到，校對頁會寫原因。沒有稿子就用聽到的字，每句都要確認
- 分段錄影逐段比，每段只拿自己的稿子對自己的聲音。整句重講時，稿子對到後面那次。斷句看句號、停頓、逗號和詞界，直式一行 12 字、橫式 18 字，設定可調
- 校對頁上面的影片就是燒出來的樣子。每句可以改字、在游標處拆開、併下句、隱藏、早晚各挪 0.1 秒，還有全部確認、全部取代、整支平移、重新對字幕、撤銷
- 樣式：白字黑邊、白字黑底、黃字黑邊，字級三檔，位置上中下。長句先縮字，縮到底還放不下才變兩行
- 預設燒 1080p，每一段都是 4K 才會出現 4K 可選。直接從各段原片輸出一支，畫質少壓一次
- 手機太燙先停下來，4K 到 serious 停，1080p 到 critical 才停。涼了會自己繼續，也可以按「照樣燒」，4K 可以改 1080p。燒錄失敗或取消，原片都不動
- 切到背景：iOS 26 用系統的背景任務，舊系統只有一小段時間，不夠就停，回來重燒
- 字幕專案存在 Application Support 的 `captions`，改字自動存，設定的「字幕專案」可以回來改、重燒。原片用硬連結放進專案，和 `takes` 互不影響。左滑刪除會把這裡的原片和燒好的影片一起刪，照片裡的留著
- SRT 用同一套對時，漏講的句子不再排進去，有一段沒辨識到會寫出來。數字改用拼音比對，稿子寫 3、聽到三算對上，語音跟隨跟著變
- 除錯資訊多了字幕辨識檢測，印這支手機有哪些中文辨識能用

目前只在模擬器測過。模擬器沒有中文辨識，用的是照稿子編出來的假辨識，情境有漏講、多講、重講、聽錯、辨識到一半失敗、完全不能辨識；過熱和空間不夠也是假的。真的語音辨識一次都還沒驗。

## 第十輪（尚未真機驗證）

- 「提詞／陪伴」拆成三件事，各選各的：看多少字（全稿、提綱、不看）、有沒有人聽、看不看自己。主畫面那顆鈕和設定頁用同一組按鈕。舊設定會自己轉，原本選陪伴的變成「不看」加「有人聽」
- 有字又有人聽時，聆聽者只用視訊通話和對位再開講，字疊在聆聽者上面，選了其他擺法就當視訊通話。橫放又有字時不顯示聆聽者
- 提綱：行首是「・」「•」「·」「‧」「●」，或「-」「*」後面有空白的行，一點一段，其餘的行照念。稿子裡一個符號都沒有，就每段只顯示第一句，第一段照念。重點用大字、不捲、不跟聲音，也不顯示時長。重點沒有稿子可以對，字幕用聽到的字
- 關掉分段時，提綱的重點合成一張，放不下就縮字，縮到底還放不下才可以捲
- 錄了幾段才在全稿和提綱之間換，會先問要不要刪；換到「不看」就先收著，滑掉 app 也接得回來
- 不看自己（預設關）：開錄後自己的畫面和構圖線淡掉，倒數時還看得到。臉不見或頭跑出畫面約 2 秒就淡回來，坐回去 1 秒再淡掉。一直沒偵測到臉就一直看得到，按停止馬上回來
- 數字用數值比：30%、百分之三十、三成當成同一個，四十講成十四會標黃。買賣、漲跌這類相反字，還有多一個或少一個「不」也標黃。校對頁那一句下面寫「稿子 30%，聽到 13%」，兩個選一個。看不出值的數字不比，人名也照舊只比音
- 這段檢查：錄完一段在背景聽一次，留用、重錄照樣馬上可以按。小卡列出數字不一樣、漏講、一字之差，最多三條，點一條從那句前半秒開始播，播放視窗裡可以重錄這段。留用之後，分段列寫「第 2 段有 1 處」。一鏡到底和接好的影片，結果在完成頁
- 沒聽到、聽一半失敗，寫「這段沒檢查到」，只有一部分失敗的也會寫出來，都不打勾，之後會再試，每支最多 3 次。語音辨識已經允許過才檢查，不會跳出來要權限。要連網時寫「聲音會送到 Apple 辨識」。設定的「錄完檢查」可以關，預設開
- 檢查時聽到的字會存著，按「加字幕」直接拿來用，同一段不辨識兩次。校對頁的「重新對字幕」一律重新辨識
- AirPods 收音：設定裡一個開關，iOS 26 以上才有，預設關。錄影中切換，停下來才生效
- 修掉錄影中按左側語音跟隨鈕沒反應：整條按鈕半透明時，錄影中收不到點擊，改成各顆自己變淡
- 刪除稿子、清空、丟棄、還原按鍵的確認都看得到「取消」

模擬器版和真機版的 Release 都編過，0 錯 0 Swift 警告。主要流程在 iOS 26.4 模擬器走過，用的是假辨識、假音量、假的臉。真機一項都還沒驗。

規劃見 [`docs/第十輪計畫.md`](docs/第十輪計畫.md)。

## 建置（沒有 Mac）

所有建置都在 GitHub Actions 的 macOS runner 上跑，見 `.github/workflows/ios.yml`。

- **編譯檢查**：每次 push 到 `main` 都會不簽章編譯一次。
- **上傳 TestFlight**：設定好下面四個 repo secrets 後，每次 push 會自動封存並上傳。沒設定時這一步會略過。

| Secret | 內容 |
|---|---|
| `ASC_KEY_ID` | App Store Connect API 金鑰的 Key ID |
| `ASC_ISSUER_ID` | Issuer ID |
| `ASC_KEY_P8` | `.p8` 檔案的內容（原文或 base64 都可以） |
| `APPLE_TEAM_ID` | Apple Developer Team ID |

API 金鑰需要能管理憑證與描述檔的權限（Admin 或 App Manager），因為簽章用的是自動簽章。

## 真機測試時回報問題

模擬器沒有相機，驗收只認真機。

在主畫面**長按麥克風圖示 1 秒**（或到「設定 → 進階」）打開除錯資訊層，按「複製」，把內容貼回來。
裡面有裝置型號、實際錄影格式與 FPS、輸出旋轉與鏡像、音訊路由、音量、臉部偵測、溫度狀態、最近的錯誤與紀錄。

## 已知待真機確認的事項

- 未錄影時音量條會不會動（第七輪起音量從 `AVCaptureAudioDataOutput` 讀）。
- 影片方向與左右是否正確（預設輸出不鏡像，預覽是鏡像）。
- 4K／60 長時間錄影的發熱與掉幀，優化開和關都要試，看除錯層的「來不及」格數。
- 接片後的影片方向、左右、聲畫同步是否和單段一致；4K 接片要等多久。
- 裁靜音會不會切到字：用的是錄影當下的音量紀錄（門檻 -45 dB，前留 0.5 秒、後留 0.8 秒），講話小聲的人要特別看。
- 停頓等人的反應時間（目前安靜 0.7 秒後暫停）會不會太敏感或太遲鈍。
- 音量鍵是否能觸發錄影，按下時會不會跳出系統音量條。
- 藍牙耳機麥克風：目前沿用系統自動音訊設定，預設用手機內建麥克風；有線與 USB 麥克風由系統自動切換。
- 語音跟隨：錄出來的影片聲音是否正常（第七輪起語音和錄音共用同一路音訊）；除錯資訊的「語音分流 收到 N 包」在錄影中會不會增加；提詞跟得上跟不上。
- 這支手機的 zh-TW 是否支援裝置端辨識（除錯紀錄會寫「裝置端」或「連網」）。
- 字幕檔的時間準不準，匯入剪映／CapCut 後有沒有對上嘴型。
- 橫式錄影：手機橫放錄出來的影片是不是正的 16:9（兩個橫放方向都要試）、左右有沒有反、鏡像開關在橫式下對不對。
- 橫放時介面的字有沒有轉到正的方向，計時那一條會不會擋到臉。
- 有人聽：還沒按錄影時聆聽者會不會點頭（要看未錄影時讀不讀得到音量）；點頭的頻率會不會太煩。
- 聆聽者短片：播放時錄出來的聲音正不正常（播放器靜音、片子沒有音軌，理論上不碰錄音）；片段切換時有沒有閃一下；各種擺法切換時自己的預覽會不會黑掉或轉錯方向；4K／60 加上播片會不會更燙。
- 視訊通話擺法：右下角自己的小窗會不會被分段列擋到。
- 頭像框：坐近、坐遠時外框有沒有貼著頭（臉部矩形換算成頭的倍率是估的）。
- 語音跟隨現在預設打開，錄出來的聲音要先聽過；有問題就到設定關掉「提詞跟著我的聲音走」。

第七輪新增（模擬器的假相機只有橫向畫面，沒有臉也沒有聲音）：

- 直式影片是不是 1080×1920 而且是正的；直式、橫式乘上鏡像開關，四種都要試。開優化和關優化各試一次。
- iPhone 17 打開 app 立刻按錄影，畫面有沒有側過去。
- 頭尾有沒有切到字，防抖「加強」時特別看結尾。
- 優化打開、關掉那一瞬間預覽會不會閃或顛倒；顏色和關掉時比有沒有偏。iOS 17 的手機要看暗部有沒有偏亮。
- 一鍵優化在暗房、逆光、黃燈、白天窗邊各按一次，臉有沒有比較好。門檻是估的，在 `LookAnalyzer`。
- 防抖：清單列出哪幾種，標準和加強看不看得出差別，頭對在框裡錄出來有沒有跑位。
- 錄影中來電、切到背景、鎖螢幕、插拔耳機，檔案有沒有留下來。
- 藍牙踏板和翻頁器：按一下是不是只跳一次，按住會不會連跳。
- 語音跟隨退回去重唸，跟不跟得上；跳完馬上開口，頭一兩個字可能漏。
- 列表長按選單和拖曳排序會不會打架；注音組字時停頓，字會不會被打斷。
- iPhone SE 的分段錄影，左側那條開關會不會擠到提詞和分段列。

第八輪新增：

- 分段錄兩段後把 app 滑掉，重開接著錄、接片、存照片；錄到一半滑掉，救回的那段能不能存進照片、能不能接片，HEVC 和 4K 都要試。
- 講到一半點頭、抬眉、歪頭、靠前的時機自不自然，會不會太頻繁；一開口就一直講、音量又很平時，可能判不到在講話。
- 4K 錄影加上聆聽者（四台播放器）會不會燙、會不會掉格。
- 提詞的陰影在亮背景下好不好讀。
- 手機講電話或插拔耳機後，聆聽者有沒有繼續動。

第九輪新增：

- 先做第 0 期檢測：裝到手機、語音辨識權限打開，開除錯資訊等幾秒，按「複製」貼回來。要看 zh-TW 能不能離線，iOS 26 的兩個新引擎支不支援、回來的是不是繁體台灣。
- 真的語音辨識：對時準不準、詞的時間準不準、斷句和三成七成的門檻合不合理，至少拿三支錄影逐句對嘴型。錯誤碼 203 現在這樣處理：沒稿子當成沒人講話，有稿子當成辨識失敗，真機上什麼時候會出現還不知道。關掉網路、關掉聽寫各試一次，看校對頁寫的原因對不對。
- 聲音中斷過的影片，被判成「沒辨識到」的句子會不會太多。
- 數字改成拼音比對後，語音跟隨有沒有變差。5、五、無同音，可能多幾個誤配。
- 校對頁注音組字：組到一半按拆開、併下句、用稿子的、撤銷、燒錄，字有沒有掉。
- 暫停時連續打字，影片上的字幕會不會閃。
- 用真的麥克風收音（模擬器沒收音，裁不到靜音），接片後切換裁靜音，重新接片再按「加字幕」，會不會開到舊的專案；裁過的片子字幕時間對不對。換外接麥克風再試一次。
- 相機方向與鏡像：直式、橫式兩個方向乘上鏡像開關，燒出來有沒有轉錯、左右反。
- HEVC 輸出能不能存進照片、傳到別的 app；顏色和原片比有沒有偏。模擬器錄的原片沒標色域，燒完亮度略偏，真機錄的標 709，要實際比。
- 單段、沒裁過的影片，AAC 聲音原封不動搬過去，要對嘴型。
- 4K 長片開燒前會先跟系統要一塊空間，畫面會不會卡住。
- 真的過熱：4K 到 serious 停、1080p 到 critical 才停；改 1080p、照樣燒、等涼了自己繼續，三種都要試。
- 燒到一半切到背景：iOS 26 的系統進度有沒有出現、做不做得完，過熱暫停時會不會被系統提早收回；舊系統做到哪裡。帶旋轉標記的影片在背景畫不出來，會停下來請你重燒，app 自己錄的是轉正的。
- 從設定進校對頁、關掉、馬上再進，預覽有沒有聲音；回主畫面後相機和收音有沒有恢復。
- 旁白：校對頁、燒錄、字幕專案列表用旁白走一遍，唸得懂、按得到。

第十輪新增：

- 這段檢查：真的辨識要等幾秒，誤報多不多，錄下一段時語音跟隨和檢查會不會互相打斷，連網辨識的次數夠不夠用。
- 數字：辨識會把數字寫成什麼樣子，四十和十四分不分得出來；辨識自己漏掉的數字會標「沒聽到」，多不多。沒驗過的有「三年半／三個半月」和「1969／2009 年」。
- 不看自己：坐遠、坐近、歪出去再坐回來，淡入淡出的時機對不對；橫放時只看臉，準不準。自己的畫面留了一點點不透明，看音量鍵快門按不按得動；暗房裡看不看得出殘影。
- 臉在錄影中進出畫面的淡入淡出，模擬器測不到。
- 提綱：重點的字夠不夠大、好不好讀，系統字級放大時會不會爆版；換成提綱、換稿之後，接著錄會不會接錯。
- 有字又有人聽：字疊在聆聽者上面，三位聆聽者各看一次讀不讀得到。
- 不看加有人聽，六種擺法都要看，模擬器只看了視訊通話和圓形頭像。
- AirPods 收音：真的有比較好，錄影中拔掉、換回手機麥克風，檔案有沒有留下來；AirPods 的音量和手機麥克風不同，停頓和裁靜音的門檻要重看。按柄開始錄影時，提示音會不會錄進去。
- 舊版升級：原本選陪伴、原本有錄到一半的段落，更新後有沒有接回來。
- 旁白：提綱重點段和「不看」時，透明的提詞、回開頭、腳本鈕會不會被念出來（模擬器的無障礙樹裡還在）。
- iPhone SE：選單、小卡、留用重錄會不會擠在一起。

模擬器測字幕：啟動參數加 `-debugFakeCaptions mixed`，其他情境看 `FakeCaptionRecognizer` 的註解。`debugBurnHeat`、`debugBurnNoSpace` 設成 YES 會假裝過熱和空間不夠。`debugFakeFace` 寫 in、out 或 none 假裝有沒有臉。這四個只在模擬器版有效。`debugFake` 開頭的都要重開 App 才讀得到新值。App 自己存過的設定，外面用 `defaults write` 蓋不掉，要用啟動參數，例如 `-promptAmount full`。

模擬器測橫式介面：`defaults write org.domyweb.broccolicam debugForceAngle -float 90`（或 -90）後重開 App，介面會當成橫放。真機上不要設這個值。
